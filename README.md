# OTP Module CyberSecurity

Учебный проект по дисциплине "Кибербезопасность".

## Что реализовано

Реализован сервис авторизации с использованием:

- хеша пароля;
- TOTP с симметричным ключом;
- проверки энтропии хоста;
- внешнего погодного API как дополнительного источника данных.

## Используемые технологии

- Python
- FastAPI
- Uvicorn
- bcrypt
- pyotp
- requests

## Запуск проекта

Активировать виртуальное окружение:

source venv/bin/activate

Запустить сервер:

uvicorn app:app --reload

После запуска Swagger UI доступен по адресу:

http://127.0.0.1:8000/docs

## API

### GET /

Проверяет, что сервис работает.

Пример ответа:

{
  "message": "OTP Module CyberSecurity is running"
}

### GET /entropy

Показывает значение энтропии системы.

На Linux читается файл:

/proc/sys/kernel/random/entropy_avail

На macOS такого файла нет, поэтому значение entropy равно null.

Пример ответа на macOS:

{
  "entropy": null,
  "has_enough_entropy": true
}

### POST /register

Регистрирует пользователя.

Пример запроса:

{
  "username": "testuser",
  "password": "testuser"
}

При регистрации:

1. Пароль хешируется через bcrypt.
2. Проверяется энтропия хоста.
3. Генерируется TOTP-секрет.
4. Данные пользователя сохраняются в users.json.

Пример ответа:

{
  "success": true,
  "message": "User registered successfully",
  "username": "testuser",
  "totp_secret": "...",
  "totp_uri": "otpauth://..."
}

### POST /login

Проверяет логин, пароль и TOTP-код.

Пример запроса:

{
  "username": "testuser",
  "password": "testuser",
  "totp_code": "123456"
}

Если все данные верные, сервис возвращает:

{
  "success": true,
  "message": "Login successful"
}

## Как работает TOTP

TOTP означает Time-Based One-Time Password.

Код генерируется на основе двух данных:

секретный ключ + текущее время

У каждого пользователя есть свой секретный ключ. Сервер хранит этот ключ и может вычислить актуальный 6-значный код.

Обычно TOTP-код меняется каждые 30 секунд.

При входе пользователь отправляет логин, пароль и TOTP-код. Сервер сначала проверяет пароль, а затем вычисляет текущий TOTP-код и сравнивает его с кодом пользователя.

## Проверка энтропии

Перед генерацией TOTP-секрета сервис проверяет энтропию хоста.

На Linux используется файл:

/proc/sys/kernel/random/entropy_avail

Если значение энтропии слишком маленькое, генерация ключа запрещается.

На macOS такого файла нет, поэтому используется системный криптографический генератор случайности os.urandom.

## Использование внешнего Random API

Для дополнительного источника данных используется Open-Meteo API.

Сервис получает погодные данные:

- температуру;
- влажность;
- скорость ветра;
- давление.

Эти данные не используются как единственный источник криптографической случайности. Они смешиваются с системной случайностью и текущим временем через SHA-256.

Схема:

системная случайность + данные погоды + текущее время -> SHA-256 -> ключевой материал

## Почему пароль хранится безопасно

Пароль пользователя не сохраняется в открытом виде.

Вместо этого используется bcrypt-хеш.

В users.json хранится примерно так:

{
  "testuser": {
    "password_hash": "$2b$12$...",
    "totp_secret": "..."
  }
}

## Плюсы решения

- пароль не хранится в открытом виде;
- используется двухфакторная авторизация;
- TOTP-код действует ограниченное время;
- TOTP-код не нужно хранить отдельно, он вычисляется по времени и секретному ключу;
- есть проверка энтропии перед генерацией ключа;
- используется внешний API как дополнительный источник данных.

## Минусы решения

- users.json подходит только для учебного проекта, в реальном сервисе нужна база данных;
- TOTP-секрет хранится на сервере и должен быть защищён;
- если TOTP-секрет украдут, злоумышленник сможет генерировать коды;
- нужно следить за временем на сервере;
- погодные данные не являются полноценным криптографическим источником случайности и используются только как дополнительный материал.

## Пример проверки TOTP через терминал

Получить текущий TOTP-код для пользователя testuser:

python -c "from auth import load_users; from totp_service import get_current_totp; u=load_users(); s=u['testuser']['totp_secret']; print(get_current_totp(s))"

Полученный код можно использовать в POST /login.
